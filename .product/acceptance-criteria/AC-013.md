# AC-013: Recipes page works when stored crop info is unreadable

- **Status:** Verified
- **User Story:** [US-003](../user-stories/US-003.md)

## Criterion

With the stored crop info replaced by unreadable content, the app starts, the recipes page lists the same recipes as it does with valid info, and hovering the "Turnip" slot on the Turnip Salad recipe card shows exactly "No info available".

## Verification Method

Note the recipe count shown on the recipes page with "Owned only" unchecked. Stop the app, replace the stored crop info's contents with random text that is not valid data, and start the app again. Open the recipes page with "Owned only" unchecked and hover the "Turnip" slot on Turnip Salad. Restore the original stored crop info afterward. Expected: the app starts without error, the page loads with the same recipe count, and the info text "No info available" is visible.

## Evidence

- **Checked:** Backed up `data/crops.json` to `tmp/us003_crops.json.bak` (same SHA-256 `A8AAEFEF…1AD1E2D4`). Made sure port 8000 was free, started the app with `python -m app`, and ran `tmp/us003_hover.py ac013_baseline`. That script drives headless Google Chrome over DevTools: it opens `http://127.0.0.1:8000/?owned=false`, reads the `.meta` line, moves the mouse pointer (real `Input.dispatchMouseEvent` mouse moves) onto the "Turnip" slot of the Turnip Salad card, and reads which info texts are visible. Then stopped the app (server, reloader, and launcher processes; port 8000 free again). Replaced the contents of `data/crops.json` with 200 random printable characters (starting `;2?w~aaIq;fW>`). Python's `json.load` rejects that content with "JSONDecodeError: Expecting value: line 1 column 1 (char 0)". Started the app again with `python -m app` and ran `tmp/us003_hover.py ac013`. Stopped the app, copied the backup back over `data/crops.json`, and compared SHA-256 hashes.
- **Result:** With valid info, the page showed "266 shown · 70 cookable now" (266 cards), and hovering Turnip showed "Season: Spring; Purchase at Miguel's Mercantile, Happy Shoppe". With the unreadable info, the app log showed "Application startup complete." with no errors, and `GET /?owned=false` returned 200 OK. The page showed "266 shown · 70 cookable now" (266 cards). Before the hover, no info text was visible; while hovering Turnip, the only visible info text was exactly "No info available" (screenshot `tmp/us003_ac013_turnip_hover.png`). The page threw no JavaScript exceptions. After restoring, `data/crops.json` has the same SHA-256 as the backup (4330 bytes).
- **Outcome:** Pass
- **Recorded by:** subagent (US-003)
- **Date:** 2026-09-27
