# AC-021: Hovering a popup row shows no info

- **Status:** Verified
- **User Story:** [US-005](../user-stories/US-005.md)

## Criterion

In the popup for the "Turnip" slot on the Turnip Salad recipe card, hovering the "Turnip" row without clicking it shows no info text.

## Verification Method

Start the app, open the recipes page with "Owned only" unchecked, click the "Turnip" slot on Turnip Salad, then move the pointer over the "Turnip" row in the popup without clicking. Expected: no info text is visible in the popup.

## Evidence

### Entry 1

- **Checked:** Started the app with `python -m app` and ran `tmp/us005_verify.py` (headless Google Chrome via the DevTools protocol, with real `Input.dispatchMouseEvent` input). On a fresh load of http://127.0.0.1:8000/?owned=false (Owned only unchecked), it clicked the "Turnip" slot on Turnip Salad, then sent a mouse move (no click) to the center of the "Turnip" row in the popup, at (679.5, 441). It used `elementFromPoint` to confirm the pointer was over the Turnip row, then read all rendered info text in the popup. Screenshot: `tmp/us005_ac021.png`.
- **Result:** The element under the pointer belonged to the row named "Turnip". Both rows stayed `aria-expanded=false` with no visible info text. The dialog `innerText` contained neither "Season" nor "No info". No JS exceptions.
- **Outcome:** Pass
- **Recorded by:** subagent (US-005)
- **Date:** 2026-09-27

### Entry 2

- **Checked:** The orchestrator's own script, `tmp/orch_verify2.py`. With the Turnip Salad "Turnip" popup open, it moved the real pointer onto the "Turnip" row name without clicking. It confirmed that the row matched `:hover`, then listed the info texts visible in the popup.
- **Result:** The Turnip row was hovered, and no info text was visible.
- **Outcome:** Pass
- **Recorded by:** orchestrator
- **Date:** 2026-09-27
