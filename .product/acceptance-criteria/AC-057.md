# AC-057: Recipes page works when stored fish info is unreadable

- **Status:** Verified
- **User Story:** [US-010](../user-stories/US-010.md)

## Criterion

With the stored fish info replaced by unreadable content, the app starts, the recipes page lists the same recipes as it does with valid info, and hovering the "Salmon" slot on the Poke recipe card shows exactly "No info available".

## Verification Method

Note the recipe count shown on the recipes page with "Owned only" unchecked. Stop the app, replace the stored fish info's contents with random text that is not valid data, and start the app again. Open the recipes page with "Owned only" unchecked and hover the "Salmon" slot on Poke. Restore the original stored fish info afterward. Expected: the app starts without error, the page loads with the same recipe count, and the info text "No info available" is visible.

## Evidence

- **Checked:** Backed up `data/fish.json` (SHA-256 `78de8dcf…9865a1`). Started the app as a fresh `uvicorn` process serving `app.main:app` on a free loopback port. Ran `tmp/us009_verify.py` (headless Google Chrome over DevTools, real `Input.dispatchMouseEvent` mouse moves). On `/?owned=false` it read the `.meta` line and hovered the "Salmon" slot on Poke. Then it stopped the app, replaced `data/fish.json` with the text `q8#zz!! not json @@ {{{ ~~ 7f3k` (not valid JSON), started a new app process, opened `/?owned=false` again, and hovered the same slot. Screenshot: `tmp/us009_ac048_salmon_hover.png`, checked by eye. Restored the original file from the backup and compared SHA-256.
- **Result:** With valid info, the page showed "266 shown · 70 cookable now" (266 cards), and hovering Salmon showed the Salmon catch text. With the unreadable info, the app log included "Application startup complete." and the page loaded. The page showed "266 shown · 70 cookable now" (266 cards). Before the hover, no info text was visible; while hovering Salmon, the only visible info text was exactly "No info available". No JavaScript exceptions. After restore, `data/fish.json` had the same SHA-256 as the backup.
- **Outcome:** Pass
