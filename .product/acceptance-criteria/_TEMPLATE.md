# AC-000: Title

- **Status:** Pending | Verified | Failed | Deprecated
- **User Story:** [US-000](../user-stories/US-000.md)

## Criterion

A single statement of observable behavior that can be checked as true or false. Use concrete example inputs and expected values where they are needed to make it unambiguous. Do not name code structure, components, or technologies. Name the source of any value that the user story and requirement do not state.

## Verification Method

The steps someone other than the author can follow to check the criterion, and the expected observable result. Do not name tools, commands, or test files; record those in Evidence when verification runs.

## Evidence

Add one entry per verification run, newest last. Never edit or remove earlier entries. Leave this empty until the first run.

### Entry 1

- **Checked:** the exact command, test, or steps run
- **Result:** what was observed
- **Outcome:** Pass | Fail
- **Recorded by:** orchestrator | subagent | verifier | user
- **Date:** YYYY-MM-DD
